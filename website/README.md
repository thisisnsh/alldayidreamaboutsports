# Website

Landing page and privacy policy for
[alldayidreamaboutsports.com](https://alldayidreamaboutsports.com), built with
[Eleventy](https://www.11ty.dev) and deployed to GitHub Pages by
[`website-deploy.yml`](../.github/workflows/website-deploy.yml) on every push to
`main` that touches `website/`.

```bash
npm install
npm run build     # → _site/
npm run serve     # local dev server
npm run verify    # asserts the built site
npm run data      # regenerate leagues/teams/crests from the live catalog
```

The build is offline: `src/_data/leagues.json`, `teams.json` and the crests are
generated by `npm run data` and committed, so a deploy never depends on the
catalog being up.

See the [root README](../README.md) for the app, backend and architecture.

The homepage demo is an embedded YouTube player. All download buttons lead to
`/comingsoon/` while the Mac App Store launch is pending; the website no longer
requests media or installers from the retired R2 download buckets.

The shared design uses warm white surfaces, pitch green and orange accents.
The homepage preview is an illustrative HTML/CSS composition; the embedded
video shows the actual app. The team directory supports name, catalog name,
team code and league searches, with accent-insensitive matching. All team
links and league shortcuts remain available without JavaScript.

`npm run verify` checks titles, descriptions, canonicals, structured data,
sitemap coverage, internal links, section links, images and orphaned pages.

The sitemap is generated from Eleventy's page collection, including every team
and league pagination result, and excludes pages marked `noindex: true`.
Verification requires exact coverage of indexable pages and rejects duplicate
or noncanonical sitemap URLs. New pages are included automatically; keep their
internal links and unique metadata in place before publishing.

Team and league directories expose `CollectionPage` / `ItemList` structured
data matching their visible links. Video metadata uses the YouTube player as
`embedUrl`; a watch-page URL is not a video file and must not be `contentUrl`.
Search descriptions and onboarding FAQs reflect the pending Mac App Store
launch. Update those alongside the download destination when the app launches.
